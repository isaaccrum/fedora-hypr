# Domain Docs

Before exploring a topic, read:

- `CONTEXT.md` at the repository root, if present.
- Relevant decisions under `docs/adr/`, if present.

This is a single-context repository. The domain glossary in `CONTEXT.md` is authoritative for naming concepts in issues, proposals, tests, and documentation. If a needed term is missing, either use the project’s existing terminology or record the gap for domain modeling.

If an existing ADR conflicts with proposed work, call out the conflict explicitly instead of silently overriding it. Domain documents are created lazily when the project resolves a domain concept or architectural decision.
